# 0003. FreeInk SDK: our fork, CrossPoint's pin plus the PaperDIY board commits

- Status: Accepted
- Date: 2026-11-12

## Context

CrossPoint gets its board profiles and drivers from the FreeInk SDK, a submodule pinned by commit
(`.gitmodules`: `https://github.com/Free-Ink/freeink-sdk.git`, `branch = main`). At our pin `6a208c0` the SDK has
no PaperDIY code: no profile and no `BoardPaperDiy`. It does have the parts the PaperDIY shares with other M5Stack
boards: the M5PM1 power-chip header `libs/hardware/BoardConfig/include/M5Pm1.h`, used by the PaperColor and
PaperMono profiles (`PaperMonoBoard.h:26`), and the LGFX panel driver
`libs/display/FreeInkDisplay/src/driver/LgfxEpdDriver.cpp`.

dcarnicer's port has the board layer as `paperdiy-reader/patches/sdk.patch`: 18 files on SDK `fb7e926`, MIT. Five
are new, the `libs/hardware/BoardPaperDiy/` library (pins, board code, LGFX panel config). The other 13 edit
existing files: the `M5PAPER_DIY` profile in `BoardConfig.h`, PaperDIY additions to the shared `M5Pm1.h`
(`sdk.patch:388`) and `LgfxEpdDriver`, and changes to `BatteryMonitor`, `InputManager`, `PowerManager` and
`SDCardManager` with its host-test stubs. Changes to the shared files also reach the PaperColor and PaperMono
builds. The port itself vendors the SDK as a plain directory.

FreeInk (`Free-Ink/freeink-sdk`, default branch `main`) merges board PRs often, but nobody has offered a PaperDIY
profile yet. The maintainer's fork `nandanito/freeink-sdk` exists (public, branches `main` and three earlier fix
branches, no `crosspaper/*` tags on 2026-11-12).

## Options considered

1. **Vendor the SDK** as dcarnicer does. Simple to edit, but the submodule and its history are gone, and every
   CrossPoint sync that moves the pin becomes a hand merge of a whole tree.
2. **Apply `sdk.patch` at build time** (a pre-build script on a pristine submodule). The pin stays upstream's, but
   what builds is not a commit anyone can check out, and a patch that stops applying breaks the build late.
3. **Wait for a PaperDIY profile in `Free-Ink/freeink-sdk`.** Cleanest, but no date, and CrossPaper cannot start.
4. **Our fork as the submodule, at CrossPoint's pin plus the board commits** (chosen). Every build is a real
   commit; the board layer is a short, reviewable series on top of upstream; it returns to upstream pins once
   FreeInk takes the profile.

## Decision

- The `freeink-sdk` submodule URL becomes `https://github.com/nandanito/freeink-sdk.git` (W1 makes the change).
- The pinned SDK commit is CrossPoint's pinned SDK commit plus the PaperDIY board-layer commits ported from
  dcarnicer's `sdk.patch`, credited to dcarnicer in the commits and in the SDK's `NOTICE`
  (`freeink-sdk/NOTICE`).
- **Publish before pin.** The SDK commit is pushed to the fork and tagged `crosspaper/<sdk-short-sha>` before any
  CrossPaper commit that pins it is pushed. Every pinned commit stays reachable through its tag. Tags are never
  moved or deleted. The working branch `crosspaper/main` may be rebased; tags may not.
- **Changing the URL:** edit `.gitmodules`, then `git submodule sync --recursive` and
  `git submodule update --init --recursive`. Never use `git submodule update --remote`: the gitlink is the truth.
- Source links (About, docs, the licence asset) name the fork, because that is where the shipped SDK source is.
- **At a CrossPoint sync**, if upstream moved its SDK pin, the remaining board commits are replayed onto the new
  upstream pin, built and host-tested, published and tagged, and then the gitlink moves. If upstream did not move
  its pin, ours stays. Board commits that upstream has absorbed are dropped from the replay. The procedure is the
  SDK section of [docs/upstream-sync.md](../upstream-sync.md).
- **Aim:** upstream the PaperDIY profile to `Free-Ink/freeink-sdk`, then go back to upstream pins. First
  coordinate with dcarnicer and prateek (CrossPoint #4005). Nandan posts; the lead drafts.

## Consequences

- Each push of a new pin is two approved pushes in order: the SDK branch and tag first, then the firmware branch.
- A fresh clone needs only `git submodule update --init --recursive`; the fork must stay public.
- Each sync that moves the pin costs a replay of the board series, until the profile is upstream.
- Wave 1 (W1) changes `.gitmodules` and the gitlink, and adds both to the seams table.
- GitHub can resolve a commit through the fork network even when no ref in our fork contains it, so "the commit
  opens on GitHub" does not prove it is published; check that the `crosspaper/<sdk-short-sha>` tag exists in
  `nandanito/freeink-sdk`.
